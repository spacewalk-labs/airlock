# learning-ingest — 링크 하나를 학습자료로

`/learning-ingest <url>` 로 불린다. 부르는 쪽은 사람이 아니라 **적재 워커**이고, 워커는
헤드리스로 너를 돌린 뒤 로그만 읽는다. 그래서 여기서 지켜야 할 것은 두 가지다.

- **되묻지 마라.** 물어볼 사람이 없다. 판단이 필요하면 스스로 정하고 이유를 로그에 남긴다.
- **§5 의 완료 표시가 성공의 유일한 근거다.** exit 0 은 근거가 아니다 — 링크가 학습자료가
  아니어서 네가 "이건 적재할 게 없습니다" 하고 곱게 끝나도 exit 0 이기 때문이다.

환경에 네 가지가 있다. 경로를 짐작하지 마라.

| 변수 | 무엇 |
|---|---|
| `AIRLOCK_LEARNING_LIBRARY` | 문서가 사는 폴더 |
| `AIRLOCK_LEARNING_SAVE` | 저장 헬퍼(`save_document.py`) — **문서가 들어가는 유일한 통로** |
| `AIRLOCK_LEARNING_RECEIPT` | 헬퍼가 이번 시도의 영수증을 쓸 자리 (네가 건드릴 일 없다) |
| `AIRLOCK_LEARNING_STATE_DIR` | 앱의 상태 디렉터리 |

이 스킬 폴더 안에 `transcript.py` 가 함께 있다. 네가 있는 자리는 스킬 파일 기준 상대경로로
찾으면 된다.

## 1. 전사본과 메타를 받는다

```bash
python3 "<이 스킬 폴더>/transcript.py" --url "<url>" --out "$AIRLOCK_LEARNING_STATE_DIR/transcript.txt"
```

JSON 한 줄이 나온다: `video_id` · `title` · `channel` · `duration` · `upload_date` · `url` ·
`subs` · `transcript_path` · `transcript_lines`.

- **exit 2** → 거기서 멈춘다. 표준오류의 문장을 그대로 사용자에게 전하고 끝낸다.
  파일을 만들지 마라. 자막이 없는 영상은 아직 지원 범위 밖이고, 그것은 실패가 아니라
  **경계**다 — 우회하려고 다른 도구를 찾지 마라.
- `subs` 가 `auto` 면 사람이 만든 자막이 아니라 **받아쓰기**다. 고유명사와 숫자가 틀릴 수
  있으므로 문서 본문 맨 위에 그 사실을 한 줄 남긴다.

메타를 받으면 **곧바로** 이 한 줄을 줄머리에서 흘린다. 적재 카드가 `dQw4w9WgXcQ 적재 중`
대신 무슨 영상인지 보여 주기 위한 것이다.

```
LEARNING-INGEST-META {"title": "<제목>", "channel": "<채널>", "duration": "<길이>"}
```

🔴 판정과는 무관하다. 빠뜨려도 적재는 성공하고 카드가 video_id 로 곱게 내려앉을 뿐이니
실패로 취급하지 마라.

## 2. 요약본을 쓴다 — 이 스킬의 본론

전사본을 읽고 **한 번에** 문서를 만든다. 조각내 여러 번 부르지 마라 — 챕터별로 나눠 부르면
앞뒤를 못 보고 같은 말을 반복한다.

문서는 마크다운이고 이 모양이다.

```markdown
---
title: "<영상 제목>"
video_id: <id>
channel: <채널>
duration: "<hh:mm:ss>"
url: <url>
source: youtube
added: <YYYY-MM-DD>
---

# <제목>

## 개요

세 문단 이내. **이 영상이 무엇을 주장하는가**를 먼저 쓴다. 다룬 주제의 목록이 아니다.

## 챕터별 요약

### 00:00:00 — <챕터 제목>

그 구간의 내용. 타임스탬프는 전사본의 `**[hh:mm:ss]**` 에서 가져온다 — 지어내지 마라.

## 남는 질문

영상이 답하지 않은 것, 확인이 필요한 것.
```

지킬 것 셋.

1. **프론트매터의 일곱 줄은 그대로다.** 저장 헬퍼가 `video_id` 로 "이 요청의 문서가 맞는지"
   를 판정한다. 빠지면 적재 전체가 실패로 기록된다.
2. **타임스탬프를 지어내지 마라.** 전사본에 있는 것만 쓴다. 요약이 틀리면 고칠 수 있지만
   없는 시각을 가리키는 링크는 사용자가 확인할 방법이 없다.
3. **길이는 영상에 맞춘다.** 10분짜리에 5,000자를 쓰지 마라. 전사본을 다시 읽는 것보다
   빠르게 이해되는 것이 목적이다.

## 3. 어느 폴더에 둘지 정한다

라이브러리를 보고 **이미 있는 폴더 중 하나**를 고른다.

```bash
ls "$AIRLOCK_LEARNING_LIBRARY"
```

- 맞는 폴더가 있으면 그것을 쓴다 (`<폴더>/<슬러그>.md`).
- 없으면 **루트에 둔다** (`<슬러그>.md`). 폴더를 새로 만들지 마라 — 남의 서랍이고,
  카테고리는 사용자가 정하는 것이다. 목록은 루트 문서를 "분류 없음" 으로 잘 보여 준다.
- 경로는 **한 단계까지만** 허용된다. 헬퍼가 그 밖을 거절한다.
- 파일 이름이 이미 있으면 헬퍼가 거절한다(`path-taken`). 라이브러리를 본 뒤에 골라도
  겹칠 수 있으니, 겹치면 슬러그 뒤에 채널이나 연도를 붙여 다른 이름을 만든다.

슬러그는 영어 소문자·숫자·붙임표로 만든다. 파일 이름은 사람이 나중에 바꿀 수 있으므로
완벽할 필요는 없다.

## 4. 저장한다 — 헬퍼를 통해서만

문서와 **렌더된 짝**을 같이 넘긴다.

```bash
python3 "$AIRLOCK_LEARNING_SAVE" --path "<폴더>/<슬러그>.md" --video-id "<id>" \
  --html "$AIRLOCK_LEARNING_STATE_DIR/<슬러그>.html" < "$AIRLOCK_LEARNING_STATE_DIR/<슬러그>.md"
```

초안은 **상태 디렉터리**에 쓴다 — 라이브러리에 직접 쓰지 않는다는 「경계」와 같은 규칙이고,
`/tmp` 와 달리 이 앱의 자리라 남의 것과 섞이지 않는다.

- 🔴 **`.html` 짝이 없으면 그 문서는 영원히 공유할 수 없다.** 공유로 나가는 것은 `.md` 가
  아니라 `.html` 이다. 짝을 잊으면 목록에는 보이는데 공유 버튼만 안 먹는 자료가 된다.
  HTML 은 네가 만든다 — 문서 하나가 담긴 최소한의 페이지면 충분하다(`<meta charset>`,
  제목, 본문). 외부 CSS 나 스크립트를 끌어오지 마라.
- 자기 도구로 라이브러리에 직접 쓰지 마라. 헬퍼가 하는 일은 검사·원자적 교체·영수증이고,
  그 영수증이 앱에게 "이 문서는 이미 도착했다" 를 말하는 유일한 신호다.
- **exit 2** 면 표준오류에 이유가 있다. 대개 프론트매터나 경로 문제이니 고쳐서 다시 부른다.
  그 상태로 §5 를 찍지 마라 — 없는 문서를 완료로 보고하는 것이 최악이다.
- 🔴 **`path-taken`** 이면 그 자리에 **다른 영상의 문서가 이미 있다.** 헬퍼가 덮지 않는다.
  슬러그를 바꿔 다시 부르라 — 지우거나 밀어내려 하지 마라. 그 문서는 사용자의 것이다.
- `[경고]` 가 찍혀도 exit 0 이면 **저장은 된 것이다.** 영수증만 못 쓴 것이니 계속 진행한다.

## 5. 완료 표시

저장이 exit 0 으로 끝난 **뒤에만**, 줄머리에서 이 한 줄을 찍는다.

```
LEARNING-INGEST-DONE <폴더>/<슬러그>.md
```

경로는 §4 에 넘긴 그것과 **글자 그대로 같아야** 한다. 워커가 이 줄을 읽어 그 자리의 파일을
직접 확인한다 — 없거나, 비었거나, 다른 영상의 문서면 적재는 실패로 기록된다.

그 뒤에 사용자에게 두세 줄로 보고한다: 무슨 영상이었고, 어디에 저장했고, 무엇이 남는
질문인지.

## 경계

- **git 을 부르지 마라.** 커밋도 브랜치도 PR 도 이 절차에 없다. 라이브러리가 마침 git
  레포일 수는 있지만 그것은 사용자 사정이고, 적재의 성공 판정과 무관하다.
- **라이브러리 밖에 쓰지 마라.** 전사본은 상태 디렉터리에, 문서는 헬퍼를 통해서만.
- **기존 문서를 고치지 마라.** 같은 영상이 이미 있으면 앱이 접수 단계에서 걸러 낸다.
  그래도 마주치면 덮어쓰지 말고 그 사실을 보고하고 끝낸다.
