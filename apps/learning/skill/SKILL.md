# learning-ingest — 링크 하나를 학습자료로

`/learning-ingest <url>` 로 불린다. 부르는 쪽은 사람이 아니라 **적재 워커**다. 헤드리스로
돌리고 로그만 읽는다.

원칙 셋.

- **되묻지 않는다.** 판단이 필요하면 스스로 정하고 이유를 로그에 남긴다.
- **성공의 근거는 §5 의 완료 표시 하나뿐이다.** exit 0 은 근거가 아니다. 아무것도 하지
  않고 끝나도 exit 0 이다.
- **문서가 들어가는 통로는 저장 헬퍼뿐이다.** 라이브러리에 직접 쓰지 않는다.

경로를 짐작하지 않는다. 환경에 넷이 있다.

| 변수 | 무엇 |
|---|---|
| `AIRLOCK_LEARNING_LIBRARY` | 문서가 사는 폴더 |
| `AIRLOCK_LEARNING_SAVE` | 저장 헬퍼(`save_document.py`) |
| `AIRLOCK_LEARNING_RECEIPT` | 헬퍼가 영수증을 쓰는 자리 (건드릴 일 없다) |
| `AIRLOCK_LEARNING_STATE_DIR` | 이 앱의 작업 자리 — 초안과 전사본은 여기에 |

`transcript.py` 는 이 스킬 폴더 안에 있다. 상대경로로 찾는다.

## 1. 전사본과 메타를 받는다

```bash
python3 "<이 스킬 폴더>/transcript.py" --url "<url>" --out "$AIRLOCK_LEARNING_STATE_DIR/transcript.txt"
```

JSON 한 줄이 나온다: `video_id` · `title` · `channel` · `duration` · `upload_date` · `url` ·
`subs` · `transcript_path` · `transcript_lines`.

도구는 정보 조회에서 확인한 자막 목록 중 사람 원어 → 다른 사람 자막 → 자동 원어 → 다른
자동 자막 순서로 하나만 골라, 그 언어를 명시해 한 번 받는다.

- **exit 2 면 거기서 멈춘다.** 표준오류의 문장을 그대로 전하고 끝낸다. 파일을 만들지 않는다.
  자막이 없는 영상은 지원 범위 밖이고, 그것은 실패가 아니라 **경계**다 — 우회 도구를 찾지
  않는다.
- `subs` 값은 프론트매터에 `subs:` 로 그대로 적는다. **본문에 자막 품질 경고를 쓰지 않는다** —
  자동 자막이라는 사실은 앱이 문서 끝에 각주 한 줄로 붙인다. 본문에 또 쓰면 읽는 사람이
  같은 말을 두 번 읽는다.

메타를 받으면 곧바로 줄머리에서 이 한 줄을 흘린다. 적재 카드에 무슨 영상인지 띄우기 위한
표시이고, 판정과 무관하다. 빠뜨려도 실패가 아니다.

```
LEARNING-INGEST-META {"title": "<제목>", "channel": "<채널>", "duration": "<길이>"}
```

## 2. 요약본을 쓴다 — 이 스킬의 본론

전사본을 **한 번에** 읽고 한 번에 쓴다. 조각내 여러 번 부르면 앞뒤를 못 보고 같은 말을
반복한다.

```markdown
---
title: "<영상 제목>"
video_id: <id>
channel: <채널>
duration: "<hh:mm:ss>"
url: <url>
source: youtube
added: <YYYY-MM-DD>
subs: <auto 또는 manual>
---

# <제목>

## 개요

이 영상이 무엇을 주장하는가. 다룬 주제의 목록이 아니다.

## 챕터별 요약

### 00:00:00 — <챕터 제목>

그 구간의 내용.

## 남는 질문

영상이 답하지 않은 것, 확인이 필요한 것.

## 이해 점검

영상의 핵심을 이해했는지 묻는 문제 5개 안팎과 각 문항의 해설.
```

지킬 것 넷.

1. **문체** — 맨 위에 한 줄 결론을 둔다. 이 영상이 결국 무슨 말인지 한 문장, 그다음 왜
   중요한지 한 문장으로 쓴다. 전문 용어는 처음 나올 때 괄호로 풀어 쓴다. 한 줄로 정의하고,
   가능하면 일상 비유를 붙인다. 짧은 문장과 능동태를 쓰고, 한 문장에는 주장 하나만 둔다.
   「개요」만 불릿을 허용하며 셋을 넘기지 않는다. 그 밖의 절은 문단으로 쓴다. 대비되는 둘은
   표로 보여 준다. 어려운 세부는 뒤로 보낸다. 쉽게 쓰다 사실이 바뀌면 실패다. 근거가 약하면
   "영상에는 없다"고 쓴다.
2. **프론트매터는 위의 여덟 줄 그대로다.** 헬퍼가 `video_id` 로 이 요청의 문서가 맞는지
   판정한다. 빠지면 적재 전체가 실패로 기록된다.
3. **타임스탬프를 지어내지 않는다.** 전사본의 `**[hh:mm:ss]**` 에 있는 것만 쓴다. 요약이
   틀리면 고칠 수 있지만, 없는 시각을 가리키는 링크는 확인할 방법이 없다.
4. **길이는 영상에 맞춘다.** 전사본을 다시 읽는 것보다 빠르게 이해되는 것이 목적이다.

이해 점검은 5문항 안팎으로 만든다. 암기가 아니라 영상의 주장과 이유를 이해했는지 묻고,
전사본에 근거가 없는 문항은 만들지 않는다. 해설에는 전사본에 실제로 있는 타임스탬프를 평문으로
남긴다. 링크와 초 계산은 앱의 결정적 후처리기가 맡으므로 직접 링크를 만들지 않는다.

오답에도 정답만큼 공을 들인다. 정답과 길이·구체성·문형을 맞추고, 화자가 반박한 통념·인접 개념
혼동·조건이 틀린 반쪽짜리 설명·원인과 결과를 뒤집은 설명처럼 그럴듯한 오해를 쓴다. 명백한
헛소리나 농담, `모두 해당`·`없음`, 정답에만 고유 용어를 넣는 방식, 오답에만 `항상`·`절대`·
`무조건`을 넣는 방식은 쓰지 않는다. `data-correct` 위치는 문항마다 달리한다. 다 쓴 뒤 문제를
가리고 보기 네 개만 봤을 때 정답이 드러나면 다시 쓴다.

저장할 HTML의 이해 점검은 공유 컴포넌트의 아래 구조를 그대로 쓴다. 페이지 전용 채점 JS를
만들거나 공용 자산 태그를 직접 넣지 않는다. `/read/` 셸이 `doc.css`와 `doc.js`를 붙인다.
각 문항의 정답 보기 하나에만 `data-correct`를 붙인다. 퀴즈의 `ol`·`ul`·`li`는 공유 컴포넌트
구조이므로 「개요」 밖의 본문 불릿 금지 규칙에서 제외한다.

```html
<section class="doc-quiz">
  <h2 class="doc-quiz-title">이해 점검</h2>
  <p class="doc-quiz-sub">암기가 아니라 핵심을 이해했는지 확인합니다.</p>
  <ol class="doc-quiz-list">
    <li class="doc-q">
      <p class="doc-q-stem">질문</p>
      <ul class="doc-q-opts">
        <li>그럴듯한 오답</li>
        <li data-correct>정답</li>
        <li>그럴듯한 오답</li>
        <li>그럴듯한 오답</li>
      </ul>
      <p class="doc-q-explain">0:00:00 — 왜 이 답인지 설명.</p>
    </li>
  </ol>
</section>
```

## 3. 어느 폴더에 둘지 정한다

```bash
ls "$AIRLOCK_LEARNING_LIBRARY"
```

**이미 있는 폴더 중에서** 고른다. 맞는 것이 없으면 루트에 둔다 — 폴더를 새로 만들지 않는다.
분류는 사용자가 정하는 것이고, 목록은 루트 문서를 「분류 없음」으로 보여 준다.

경로는 한 단계까지만 허용된다. 새 문서 이름은 반드시
`<적재일 YYYY-MM-DD>--<슬러그>--<video_id>.md` 로 만든다. 슬러그에는 영어 소문자·숫자·
붙임표만 쓴다. 파일 이름의 적재일은 프론트매터 `added`와, 끝의 video_id는 프론트매터
`video_id`와 같아야 한다. 이름이 이미 있으면 헬퍼가 거절하니, 슬러그 뒤에 채널이나 연도를
붙여 다른 이름을 만든다. 이미 저장된 문서의 옛 이름은 바꾸지 않는다.

## 4. 저장한다 — 헬퍼를 통해서만

초안은 상태 디렉터리에 쓰고, 문서와 **렌더된 짝**을 함께 넘긴다.

```bash
python3 "$AIRLOCK_LEARNING_SAVE" \
  --path "<폴더>/<적재일 YYYY-MM-DD>--<슬러그>--<video_id>.md" --video-id "<video_id>" \
  --html "$AIRLOCK_LEARNING_STATE_DIR/<슬러그>.html" < "$AIRLOCK_LEARNING_STATE_DIR/<슬러그>.md"
```

- **`.html` 짝이 없으면 그 문서는 공유할 수 없다.** 공유로 나가는 것은 `.md` 가 아니라
  `.html` 이다. HTML 은 직접 만든다 — `<meta charset>` · 제목 · 본문이면 충분하고, 외부
  CSS 나 스크립트를 끌어오지 않는다.
- **exit 2 면 고쳐서 다시 부른다.** 표준오류에 이유가 있다. 그 상태로 §5 를 찍지 않는다 —
  없는 문서를 완료로 보고하는 것이 최악이다.
- **`path-taken` 은 다른 영상의 문서가 이미 그 자리에 있다는 뜻이다.** 지우거나 밀어내지
  않는다. 파일 이름의 날짜와 이 요청의 video_id 는 유지하고 슬러그를 바꿔 다시 부른다.
  그 문서는 사용자의 것이다.
- `[경고]` 가 찍혀도 exit 0 이면 저장은 된 것이다. 영수증만 못 쓴 것이니 계속 진행한다.

## 5. 완료 표시

저장이 exit 0 으로 끝난 **뒤에만**, 줄머리에서 이 한 줄을 찍는다. 경로는 §4 에 넘긴 것과
글자 그대로 같아야 한다. 워커가 이 줄을 읽고 그 자리의 파일을 직접 확인한다.

```
LEARNING-INGEST-DONE <폴더>/<적재일 YYYY-MM-DD>--<슬러그>--<video_id>.md
```

그 뒤에 두세 줄로 보고한다: 무슨 영상이었고, 어디에 저장했고, 무엇이 남는 질문인지.

## 경계

- **git 을 부르지 않는다.** 라이브러리가 마침 git 레포일 수는 있지만 그것은 사용자 사정이고,
  적재의 성공 판정과 무관하다.
- **라이브러리 밖에 쓰지 않는다.**
- **기존 문서를 고치지 않는다.** 같은 영상이 이미 있으면 앱이 접수 단계에서 걸러 낸다.
  그래도 마주치면 그 사실을 보고하고 끝낸다.
