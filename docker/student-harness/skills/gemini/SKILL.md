# Gemini에 위임하기 (gemini)

긴 문서·코드를 **한 번에** 훑거나, **다른 모델의 시선**이 필요할 때 Gemini CLI에 맡깁니다.
컨텍스트가 커서 "통째로 읽고 요약·분석"에 강합니다.

## 언제

- 아주 긴 문서·로그·코드 묶음을 **한 번에** 분석해야 할 때.
- Claude와 **다른 관점의 2차 의견**이 필요할 때. 같은 모델에게 두 번 묻는 것은 검증이 아닙니다.

## 설치 (에이전트가 대신 가능)

```bash
command -v gemini >/dev/null || npm i -g @google/gemini-cli   # Node ≥ 20 필요
gemini --version
```

> 설치·명령은 공식 문서가 정본입니다: <https://github.com/google-gemini/gemini-cli>

## 인증 — 각자 자기 키를 씁니다 (무료)

🔴 **구글 계정 로그인(OAuth) 안내를 따라가지 마세요.** 그 무료 경로는 2026-06-18에 닫혔습니다.
지금 쓰는 것은 **API 키**이고, 이쪽은 무료로 남아 있습니다.

1. <https://aistudio.google.com/apikey> 에서 **API 키를 발급**합니다.
   **빌링(결제수단)을 연결하지 않으면 무료 한도로 유지**됩니다 — 연결하는 순간 유료로 넘어갑니다.
2. 무료 한도는 **구글 계정·프로젝트 단위**입니다. 남과 키를 나눠 쓰면 한도도 같이 씁니다.
   **각자 자기 키를 발급하세요.**
3. 키는 **금고에 넣습니다.** 평문 파일·코드·채팅에 절대 남기지 않습니다
   (절차 = [`secret-manage`](../secret-manage/SKILL.md)):

```bash
# 금고에 GEMINI_API_KEY 라는 이름으로 저장한 뒤, 실행 순간에만 주입합니다
bws run -- gemini -p "이 저장소의 구조를 요약해줘"
```

> 왜 `export GEMINI_API_KEY=...` 로 안 하나: `export` 한 값은 셸 히스토리·프로세스 목록·
> 크래시 로그에 남습니다. `bws run` 은 그 프로세스에만 넣고 끝냅니다.

## 쓰는 법

```bash
bws run -- gemini -p "<질문>"                    # 한 번 묻고 답만 받기
bws run -- gemini -p "$(cat 긴문서.md)  위 문서를 500자로 요약해줘"
```

- **결과는 그대로 믿지 말고 원문과 대조**합니다. 긴 입력일수록 없는 내용을 지어낼 여지가 큽니다.
- 2차 의견으로 쓸 때는 **"반박해 보라"** 고 시키세요. "확인해 달라"는 대개 동의만 돌려받습니다.

## 하지 말 것

- 키를 채팅·커밋·`.env` 평문에 남기기.
- 남의 키 빌려 쓰기 — 무료 한도가 계정 단위라 둘 다 막힙니다.
- 고객 정보·개인정보를 붙여 넣기. 다른 회사 모델에 보내는 것입니다.
