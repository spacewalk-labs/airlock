# 작업 로그 (worklog)

한 일을 **시간순으로 파일에 쌓아** 두는 습관입니다. 스테이트리스인 에이전트에게는 이 로그가 곧
**바깥에 저장한 기억**이고, 사람에게는 "그때 왜 이렇게 했더라"를 되짚는 근거가 됩니다.

## 어디에

**작업 중인 레포 루트의 `WORKLOG.md` 한 파일** — 없으면 만들고, 있으면 **맨 아래에 이어 붙입니다**.
회고는 그 일이 있었던 레포 안에 남깁니다. 홈(`~`)에 로그 폴더를 따로 만들지 않습니다.

> 🔴 **반드시 파일 맨 아래에 append 합니다(최신이 아래로).** 세션 시작 훅이 이 파일을 `tail` 로
> — 즉 **끝에서부터 마지막 40줄** — 읽어 지난 맥락을 되살리기 때문입니다. 맨 위에 쓰면 훅이
> **가장 오래된** 40줄을 읽어 이어받기가 조용히 무력해집니다. 다른 파일에 적어도 훅이 못 찾습니다.

## 언제 적나

- 작업 한 덩어리를 **끝냈을 때**, 중요한 **결정**을 내렸을 때, **막혔다가 푼** 순간.
- `session-close`가 세션을 닫을 때 **요약을 이 로그에 append** 합니다(둘은 짝).

🔴 **빈 회고 금지.** 삽질도, 설명이 필요한 결정도 없이 매끄럽게 끝난 세션의 로그는 **커밋 메시지
재탕**이라 자산이 아니라 소음입니다. 남길 게 없으면 **안 남깁니다.**

## 세 가지의 역할 경계

| 무엇 | 남기는 것 |
|---|---|
| `worklog` | **결정과 그 이유** — 코드만 봐선 모를 판단. 오래 남는 기록 |
| [`session-handoff`](../session-handoff/SKILL.md) | 지금 끊고 **바로 이어가기 위한 포인터** — 일회성 |
| [`session-close`](../session-close/SKILL.md) | 세션 **마감 절차** — 위 둘을 부르고 정리까지 |

## 형식 (한 항목)

```markdown
## 2026-07-25 — <한 줄 제목>
- 한 일: (실제로 바꾼 것·내린 결정)
- 왜: (코드만 봐선 모를 이유·판단)
- 다음: (남은 일·미해결)
```

- **날짜는 절대 날짜로**("어제" ❌ → `2026-07-25` ✅).
- 새 항목은 **파일 맨 끝에** 붙입니다(위의 훅 이유).

## 주의

- **사실만.** 안 한 걸 했다고 적지 않습니다. 추정은 "추정"이라 표시.
- **시크릿 금지.** 토큰·키·비밀번호 값은 로그에도 남기지 않습니다(이름/참조만).
- 로그는 **덧붙이기만**, 과거 항목을 함부로 고쳐 쓰지 않습니다.

## 출력

```
worklog 기록: <파일> 맨 아래에 "<제목>" 추가 (2026-07-25)
```
