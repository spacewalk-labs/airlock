# cad-read — 캐드 도면에서 데이터를 뽑는다

**읽기 전용이다.** 도면을 생성·수정·저장하지 않는다. 그려 달라는 요청이 오면 이 스킬이 아니라고 말하고
무엇을 대신 할 수 있는지 안내한다.

## 0. 먼저 입력이 무엇인지 가른다

| 입력 | 어디로 |
|---|---|
| `.dxf` | **여기.** ezdxf 로 바로 읽는다 |
| `.dwg` | **여기.** 단 ODA File Converter 로 DXF 변환이 먼저다 → [references/dwg-setup.md](references/dwg-setup.md) |
| `.pdf` 도면 | **여기가 아니다.** 벡터·이미지·스캔이 섞여 있어 파서가 아니라 OCR/VLM 파이프라인이 푼다. 이 스킬로는 못 푼다고 알리고, 원본 DWG·DXF 를 받을 수 있는지 먼저 묻는다 |
| `.ifc` `.step` `.dgn` `.rvt` | 범위 밖. ezdxf 로 안 열린다고 알리고 필요하면 별도 도구를 논의한다 |

DWG 를 받았고 변환기가 없으면 **DXF 재수출을 요청하는 편이 대개 싸다.**

## 1. 절차 — probe 로 좁힌 다음에만 뽑는다

실무 도면은 엔티티가 수만 개다. 통째로 덤프하면 컨텍스트만 태우고 답은 요약 안에 있다.
**probe → 필요한 레이어 확정 → text/geom** 순서를 지킨다.

스크립트 경로는 박스마다 다르므로 하드코딩하지 말고 그 자리에서 푼다:

```bash
CAD=$(for r in ~/.claude/skills ~/.agents/skills .claude/skills; do
        [ -f "$r/cad-read/scripts/cadread.py" ] && echo "$r/cad-read/scripts/cadread.py" && break
      done)
```

`uv` 가 의존성(ezdxf)을 자동으로 잡으므로 사전 설치가 필요 없다. `uv` 가 없는 박스면
`pip install --user ezdxf` 후 `python3 "$CAD" ...` 로 부른다.

```bash
"$CAD" probe 도면.dxf                      # ① 단위·범위·레이어·엔티티 인구조사 (항상 먼저)
"$CAD" text  도면.dxf --explode            # ② 모든 문자 (블록 안까지)
"$CAD" text  도면.dxf --grep 면적          # ②' 찾는 말만
"$CAD" geom  도면.dxf --layer A-WALL       # ③ 길이·닫힌 외곽선 면적·bbox
```

각 서브명령의 전체 옵션은 `"$CAD" <서브명령> --help`. 스크립트가 못 하는 것(해치 경계, 스플라인,
블록 스케일·회전, 도면 이미지 렌더링, 대용량 스트리밍)은 [references/recipes.md](references/recipes.md)
에 ezdxf 코드 조각으로 있다 — **그런 요구가 나올 때만** 읽는다.

## 2. 숫자를 보고하기 전에 반드시 확인할 것

아래는 스크립트가 처리하거나 표시해 주는 것들이다 — **출력에 뜬 경고를 그냥 넘기지 않는다.**

**① 단위** — DXF 좌표는 단위 없는 실수다. `probe` 의 `units` 가 `unitless   <- NOT declared`
로 뜨면 저자가 단위를 선언하지 않은 것이고, 그때 `5000` 은 5000mm 일 수도 5000m 일 수도 있다.
도면 크기(extents)와 상식으로 추정하되 **추정했다고 밝히고 보고**한다. mm 가정으로 면적을 m² 로
바꾸려면 20,000,000 → `/1e6` = 20㎡.

**② 축척(scale)과 단위는 다른 축이다.** 모형공간(model space)은 보통 실척 1:1 이고 축척은
배치공간(layout)의 뷰포트에 붙는다. "1:200 도면"이라는 말이 모형공간 좌표를 200 으로 나누라는
뜻이 **아니다.**

**③ 블록 정의 안의 TEXT 는 기본 순회에 안 잡힌다.** 표제란·실명·도면번호는 블록(INSERT) 안에 있다.
그중 **ATTRIB(속성)은 `text` 가 기본으로 읽지만**, 블록 정의 안에 박힌 일반 TEXT 는 `--explode`
를 줘야 나온다. **글자가 "없다"고 결론 내리기 전에 `--explode` 를 한 번 더 돌린다.**

**④ 도면 범위(extents)는 캐시다.** 헤더의 `$EXTMIN/$EXTMAX` 는 마지막 regen 시점 값이라
비어 있거나(`±1e20`) 낡아 있다. `probe` 가 `source:` 줄에 헤더에서 읽었는지 엔티티에서 다시
쟀는지 밝히므로 그 줄을 함께 본다.

**⑤ 거울상 블록의 좌표는 뒤집혀 있다.** 엔티티는 자기 좌표계(OCS)를 들고 있어 extrusion 이 `-Z` 면
X 부호가 반대다. 스크립트 출력은 이미 WCS 로 변환돼 있으니, **recipes 의 코드를 직접 쓸 때만**
`ocs().to_wcs()` 를 챙긴다.

## 3. 보고 방식

- 면적·길이는 **단위를 명시**한다. `20000000` 이 아니라 `20,000,000 mm² (= 20㎡, 단위 미선언이라 mm 가정)`.
- 근거는 **레이어명과 좌표**로 댄다 — 도면에서 되찾을 수 있어야 한다.
- 닫힌 폴리라인이 아닌 것의 면적은 계산하지 않는다. `geom` 의 `closed` 칸이 `open` 이면
  면적 0 이 맞고, 그걸 실면적으로 보고하지 않는다.
- 자기교차 폴리라인의 shoelace 면적은 틀린다. 값이 상식과 크게 다르면 그렇게 말한다.
- **곡선은 직선으로 근사해 잰다.** `geom` 은 폴리라인의 호(bulge)를 짧은 직선들로 펴서 길이·면적을
  구하며 기본 오차 한계는 도면 단위 1.0 이다. m 단위 도면이거나 정밀한 값이 필요하면
  `--precision 0.01` 처럼 낮춘다. 근사값이라는 사실을 보고에 함께 적는다.
