# 독립 검증 게이트 (self-verify)

중요한 결과를 **"다 됐다 / 고쳤다 / 안 깨졌다 / 없다"** 라고 선언하기 직전에 통과하는 게이트입니다.
핵심은 **스스로 다시 보는 게 아니라, 아무것도 모르는 독립 에이전트가 내 결론을 깨 보게** 하는 것입니다.
사람은 자기가 방금 한 일에 관대해서, 자기 리뷰는 게이트로 치지 않습니다.

## 언제 (꼭)

- 커밋·머지·배포 직전
- "버그 없음 / 다 고침 / 링크 안 깨짐 / 테스트 통과"처럼 **단정하는 결론** 직전
- 되돌리기 어렵거나 남에게 영향 가는 작업 직전

## 방법

1. **검증할 주장을 한 문장으로** 못박습니다. 예: "이 함수는 빈 입력에서도 안 터진다",
   "발행 링크 3개 모두 200이다".
2. **근거를 말이 아니라 산출물로 묶습니다** — 바뀐 파일·diff·실제로 실행한 명령의 출력.
3. **독립 서브에이전트를 1개** 띄우고, 역할을 **"반박해 보라"**로 줍니다:
   > 다음 주장을 반박(refute)해 보세요. 반례·놓친 경우·틀린 가정을 찾는 게 목표입니다.
   > **애매하면 기본값은 "반박됨(실패)"** 입니다. 아래 판별 프로브를 산출물에 대고 돌리고,
   > 뒤집는 근거를 **파일:줄번호와 실제 값**으로 대세요. 주장: ⟨…⟩

   🔴 여러 개 띄워 **과반으로 정하지 않습니다.** 적대 검증은 **한 건이라도 뒤집히면 멈추는** 게 원칙입니다.
4. 뒤집혔으면 → **선언하지 말고** 그 문제부터 고칩니다. 고친 뒤 이 게이트를 다시 돕니다.
   검증 에이전트가 **아무 답도 안 하거나 멈췄으면 통과가 아닙니다** — 다시 돌립니다.

## 판별 프로브 (반박 에이전트가 산출물에 대고 돌린다)

1. **검색 도구의 조용한 실패** — "grep 해 보니 없다"는 "없다"가 아닙니다. 검색 도구는 `.gitignore`에
   걸린 파일을 **말없이 건너뛰어** 있는 걸 "없음"으로 만듭니다.
   → `git ls-files` 로 대상 목록을 **교차 확인**하고, **분명히 있는 문자열로 양성 대조**를 함께 돌려
   그 검색이 실제로 찾아내긴 하는지부터 봅니다(양성 대조가 실패하면 "없음"은 무효).
2. **내 코드가 실패를 숨기지 않나** — 조용한 `continue`, 빈 리스트·`None` fallback, `except: pass`.
   실패가 성공이나 "결과 없음"으로 흘러가면 테스트가 초록이어도 아무것도 증명하지 못합니다.
   → 실패 경로를 일부러 만들어 **에러가 밖으로 드러나는지** 확인합니다.
3. **부분을 전체로 일반화하지 않았나** — 파일 단위가 아니라 **줄 단위**, 섹션이 아니라 **항목 단위**로
   봤는지. "3개 확인했으니 전부 괜찮다"는 전수조사가 아닙니다.

## 주의

- **직접 실행으로 확인 가능한 건 실제로 실행**합니다(테스트·빌드·`curl`·재현). 말로만 검증하지 않습니다.
- 이 게이트로 **반만** 잡히는 것(규칙이 아예 안 걸리는 설계 결함, 실패를 스스로 숨기는 코드)은
  자동화(훅·CI)·단일 정본으로 막아야 합니다 — 검증으로 대신할 수 없습니다.

## 출력

```
검증한 주장: …
독립 에이전트 판정: 통과 | 반박됨 (근거: …)
→ 결론: (통과했으면 선언 / 반박됐으면 고칠 것) · 아직 확인 안 된 것: …
```
