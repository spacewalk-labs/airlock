# 지침 파일 정원사 (claude-md-gardener)

`CLAUDE.md`(= Codex용 `AGENTS.md`)는 시간이 지나면 **낡은 규칙·모순·군더더기**가 쌓입니다.
이 스킬은 그 파일을 **만들고**, **짧고 정확하게** 유지합니다. 규칙은 지킬 것만 남을 때 힘이 있습니다.

> **경계:** 여기서 다루는 건 **에이전트가 읽고 지키는 규칙 텍스트**입니다. 정말 일어나면 안 되는 일은
> 글로 적어 부탁하지 말고 `settings.json` 의 `deny`/`ask` 로 **막습니다** — 그건
> [`harness-gardener`](../harness-gardener/SKILL.md) 소관입니다. "금지"라고 세 번 적혀 있는 규칙을
> 보면 대개 규칙이 아니라 막을 것입니다.

## 언제

- 지침이 실제 내 방식과 어긋난다고 느낄 때
- 규칙이 너무 길어지거나, 최근에 새 습관·도구가 생겼을 때
- **새 레포에 `CLAUDE.md`/`AGENTS.md` 가 아직 없을 때**(아래 "처음 만들기")
- 몇 주에 한 번 정기 점검(세션 닫을 때 겸사겸사)

## 처음 만들기 (없는 레포)

[`repo-bootstrap`](../repo-bootstrap/SKILL.md) 이 만드는 새 레포에는 이 두 파일이 **없습니다.**
없으면 이 스킬이 표준 한 벌을 만들어 넣습니다 — **그 레포에만 해당하는 것**만 적습니다.

- 빌드·테스트·실행 명령(실제로 돌려 보고 적습니다) · 폴더 구조에서 헷갈릴 만한 것
- 이 레포에서만 다른 규칙(브랜치 이름·커밋 규칙·건드리면 안 되는 파일)
- 전역 `~/.claude/CLAUDE.md` 에 이미 있는 것은 **다시 적지 않습니다**(두 벌이 되면 갈라집니다).
- `AGENTS.md` 는 같은 내용의 심링크로 두는 게 가장 안 어긋납니다: `ln -s CLAUDE.md AGENTS.md`

## 교훈 하나가 생겼을 때 — 어디로 보내나

아래 "순서"는 **이미 적혀 있는 것**을 손질합니다. 방금 배운 것을 **애초에 어디 적을지**는 이 표가
가릅니다. 전부 `CLAUDE.md` 로 밀어 넣으면 비대와 모순이 그 자리에서 생깁니다.

| 이런 교훈이면 | 어디로 |
|---|---|
| **매번 걸리는 원칙** — "앞으로 ~할 때마다" | `CLAUDE.md` 에 **1~3줄** |
| **가끔 오는 상황의 절차** — "이런 일이 생기면 이 순서로" | **스킬**로 ([`create-skill`](../create-skill/SKILL.md)) |
| **정말 일어나면 안 되는 것** | 글이 아니라 `settings.json` 의 `deny`/`ask` |
| **일회성** — 이미 고쳐진 것, 그때만 맞는 것 | **버립니다.** 또 나오면 그때 적습니다 |
| **한 번인지 반복인지 모르겠다** | **두 번 볼 때까지 기다립니다.** 한 번 보고 규칙으로 만들면 과적합입니다 |

## 순서

1. **CLAUDE.md 를 통째로 읽습니다.** 각 규칙에 대해 물어봅니다:
   - 지금도 **사실인가?**(도구·경로·이름이 안 바뀌었나 — 바뀐 건 실제로 확인)
   - **실제로 지키고 있나?** 안 지키는 규칙은 지우거나 고칩니다.
   - 다른 규칙과 **모순되지 않나?** 겹치면 하나로 합칩니다.
2. **낡은 것(stale) 훑기 — 느낌이 아니라 실제로 확인합니다.** (`CLAUDE.md` 가 있는 폴더에서)
   - **경로는 전수 존재 확인.** 문서가 가리키는 파일·폴더·스킬 링크를 **하나도 빼지 말고** 확인합니다.
     없는 것을 가리키는 줄은 죽은 규칙입니다(`<이름>` 같은 자리표시자는 걸러 읽습니다).
     ```bash
     grep -oE '`[^`]+`' CLAUDE.md | tr -d '`' | grep -E '^(~|\.?/)' | sort -u \
       | while read -r p; do [ -e "${p/#\~/$HOME}" ] || echo "없는 경로: $p"; done
     grep -oE '\]\([^)]+SKILL\.md\)' CLAUDE.md | tr -d ']()' | sort -u \
       | while read -r p; do [ -e "$p" ] || echo "없는 스킬: $p"; done
     ```
   - **폐기된 이름 grep.** 안 쓰기로 한 도구·명령·스킬 이름을 직접 찾습니다
     (`grep -rn '<옛이름>' CLAUDE.md AGENTS.md`). 이름만 바뀐 것은 조용히 살아남습니다.
   - 🔴 **라이브 문서와 과거 기록을 구분합니다.** 손대는 건 **지금 지키라고 있는 문서**(`CLAUDE.md`·
     `AGENTS.md`·`.claude/` 규칙)뿐입니다. **회고·`WORKLOG.md`·로그·아카이브는 그때 사실의 기록**이라
     경로가 죽었어도 **고치지 않습니다** — 고치면 기록이 아니게 됩니다.
2a. **인용은 한 건씩 원문에 대 봅니다.** 지침이 다른 파일을 큰따옴표로 옮겨 적고 있으면
   **기억으로 믿지 말고 찾아봅니다.** 🔴 줄번호까지 붙은 인용일수록 더 믿게 되므로 틀렸을 때 피해가 큽니다.

   ```bash
   grep -cF -e "<인용 문구>" <원문파일>              # ① 지금 있나
   git log --oneline -S"<인용 문구>" -- <원문파일>    # ② 예전에 있던 적은 있나
   ```

   | ① 지금 | ② 과거 | 뜻 | 처방 |
   |---|---|---|---|
   | 있음 | — | 정상 | 그대로 |
   | 없음 | 있음 | 원문이 바뀐 것 | 지금 문장으로 인용을 갱신 |
   | 없음 | 없음 | 🔴 **처음부터 없던 문장** | 정정하고, **가짜였다는 사실을 남깁니다** |

   마지막 칸이 중요합니다 — 그냥 지우면 다음에 같은 인용이 되살아납니다.
   **새로 인용할 때도 같습니다: 옮겨 적기 전에 원문을 `grep` 합니다.**

2b. **나쁜 문장은 세지 말고 그 자리에서 고칩니다.**

   | 무엇 | 왜 해로운가 | 어떻게 |
   |---|---|---|
   | **절대·항상·전부·무조건** | 반례 하나로 무너지는데, 무너진 뒤에도 문장은 남아 다음 세션을 그쪽으로 밉니다 | 범위를 붙입니다 — 언제·어디서 참인지 |
   | **근거 없는 단정** | 한 번 보고 "그렇다"로 적으면 표본이 전체가 됩니다 | 무엇을 언제 쟀는지 붙입니다 |
   | **"아마·~인 듯·같다"** | 불확실을 **사실처럼** 저장한 것이라, 읽는 쪽은 그 머뭇거림을 못 봅니다 | 확인해서 단정하거나, `미확인` 이라고 못 박고 확인 방법을 적습니다 |
   | **날짜 없는 "완료·해결됨"** | 언제인지 모르면 지금도 맞는지 알 수 없습니다 | 날짜를 붙입니다 |

   🔴 **목록으로 쌓지 말고 고치고 지나갑니다.** 이런 걸 목록으로 만들면 그 목록이 다음 점검의
   소음이 되고, 길어질수록 사람은 전부를 후보로 보고 결국 아무것도 안 고칩니다.
   세어서 보고할 것은 **사람이 판단해야 하는 것**(모순·죽은 경로·가짜 인용)뿐입니다.
   단, **뜻은 바꾸지 않습니다** — 머뭇거림을 지우는 것과 불확실을 확정으로 바꾸는 것은 다릅니다.

3. **최근 대화에서 반복된 지시**를 봅니다. 사용자가 여러 번 교정한 것 → 규칙으로 승격.
   한 번뿐인 상황별 지시 → 규칙으로 올리지 않습니다.
4. **길면 줄이기 전에 구조를 봅니다.** 🔴 **길이는 원인이 아니라 증상입니다.**
   처방 순서가 있고, **압축이 맨 마지막**입니다:
   ① **라우팅** — 본문은 "무엇이 어디 있나"만 남기고 → ② **옮기기** — 긴 설명은 별도 파일로
   원문 그대로 → ③ **색인** — 목록은 포인터로 → ④ 그래도 남으면 압축.
   문장을 조여 정보를 잃는 것보다 층을 나누는 편이 낫습니다.
   그리고 한 규칙 = 한 줄 원칙, 예시는 꼭 필요할 때만.
5. **AGENTS.md 동기화 확인.** `AGENTS.md`가 `CLAUDE.md` 심링크면 그대로 두고, 별도 복사본이면
   내용이 같은지 확인해 맞춥니다(Claude·Codex가 같은 규칙을 보게).
6. **바꾸기 전 사용자에게** 무엇을 왜 지우고/고칠지 요약해 확인받습니다. 지침은 사용자의 것이므로
   임의로 갈아엎지 않습니다.

## 하지 말 것

- 사용자 승인 없이 규칙을 **통째로 재작성**하지 않습니다(최소 변경).
- "있으면 좋을 것 같은" 규칙을 **추측으로 추가**하지 않습니다 — 실제 반복된 것만.
- **지우기 전에 커밋합니다.** 지운 규칙을 되살릴 방법이 `git` 말고 없다면, 지우기 전 상태가
  커밋돼 있어야 합니다. 안 그러면 되돌릴 수 없습니다.

## 한 번 하고 끝내면 되돌아옵니다

정돈은 1회성으로 하면 **반드시 원상복귀합니다.** 그래서 손질 자체보다 **언제 또 할지**를 정해 두는 편이
중요합니다 — [`session-close`](../session-close/SKILL.md) 로 세션을 닫을 때 겸사겸사가 가장 잘 붙습니다.
"다음에 시간 나면"은 안 옵니다.

## 출력

```
점검한 규칙 수: N
죽은 참조: 경로 N개 / 스킬 링크 N개 / 폐기된 이름 N곳  (과거 기록은 제외)
인용 대조: 정상 N / 원문이 바뀌어 갱신 N / 🔴 원문에 없던 것 N
그 자리에서 고친 문장: N줄  (판단이 필요 없는 것 — 목록으로 올리지 않음)
제안: 삭제 … / 수정 … / 승격 … / settings.json 으로 넘길 것 …
AGENTS.md 동기화: OK / 맞춤
```
