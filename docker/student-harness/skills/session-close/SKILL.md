# 세션 닫기 (session-close)

일이 한 덩어리 끝났거나 대화를 마무리할 때 이 순서로 마감합니다. 목적은 **다음 세션(또는 다른
에이전트)이 헤매지 않고 그대로 이어받게** 하는 것입니다.

> **자매 스킬**: 세션을 **열 때** = [`session-resume`](../session-resume/SKILL.md) ·
> 컨텍스트가 차서 **중간에 끊고 이어갈 때** = [`session-handoff`](../session-handoff/SKILL.md) ·
> 여기(session-close)는 **일을 접는 마감**입니다.

## 언제

- 하나의 작업(기능·문서·조사)이 끝났을 때
- 대화가 길어져 곧 정리될 것 같을 때
- 사용자가 "정리하고 마치자 / 세션 닫자"라고 할 때

## 순서

1. **한 일 요약** — 이번 세션에서 실제로 **바꾼 파일·내린 결정·확인한 것**을 3~6줄로 정리합니다.
   추측이 아니라 실제로 한 것만.
2. **검증 상태 확인** — 무엇을 검증했고(테스트·빌드·실행), 무엇이 **아직 확인 안 됐는지**,
   그래서 어떤 위험이 남는지 분명히 적습니다. 결과가 중요하면 여기서
   [`self-verify`](../self-verify/SKILL.md)를 돌립니다.
3. **다음에 이어갈 메모** — 다음이 바로 이어받도록 남깁니다:
   - 남은 할 일 / 미해결 질문
   - 왜 그렇게 했는지(코드만 봐선 모를 판단·이유)
   - 상대 날짜는 **절대 날짜로** 적습니다("내일" ❌ → "2026-07-27" ✅).
   메모는 [`worklog`](../worklog/SKILL.md)에 **한 항목으로 append** 하는 걸 기본으로 합니다
   (레포 루트 `WORKLOG.md`). worklog를 안 쓰면 `NOTES.md`·`docs/`에 남기되, **없으면 어디에
   남길지 사용자에게 한 번 확인**합니다.
4. **워크트리 회수 — 회수 절차의 정본은 여기입니다** ([`ship`](../ship/SKILL.md)·
   [`session-resume`](../session-resume/SKILL.md)도 같은 절차를 씁니다). "일 하나 = 워크트리 하나"이니
   끝난 워크트리는 거둡니다. 안 거두면 폴더와 브랜치만 쌓입니다. 머지까지 갔으면 `ship` 이
   **이 절차로 이미 회수했습니다** — 여기서 할 일이 없습니다.
   ```bash
   cd ~/workspace/<레포>       # 본진에서 실행합니다(지울 폴더 안에 서 있으면 안 됩니다)
   git worktree list           # 지금 무엇이 어디에 펴져 있나
   ~/.claude/skills/session-close/scripts/retire-worktree.sh <워크트리경로>
   ```
   - **회수는 이 스크립트 하나로 합니다**(Paseo 면 **Archive workspace**). 폴더 + 로컬 브랜치 +
     **원격 브랜치**까지 함께 거두고, 커밋 안 한 변경·머지 미확인·본진·기본 브랜치·내가 서 있는
     폴더면 **아무것도 지우지 않고** 사유만 냅니다(`--force` 안 씀).
   - 🔴 **머지 판정은 PR 상태(`gh`)로 합니다 — `git branch --merged` 는 squash 머지를 못 잡습니다.**
   - **이번 세션에서 내가 만든 워크트리는 그대로 회수하고, 그 밖의 것(지난 세션·남의 것)은 사용자
     승인을 받은 뒤** 회수합니다. 스크립트는 누가 만들었는지 모릅니다 — 지목은 사람 몫입니다.
     🔴 스크립트가 삭제까지 직접 하므로 **하네스의 확인 프롬프트(`git worktree remove` 등)가
     따로 뜨지 않습니다.** 위 승인 규칙이 그 자리를 대신하니, 물어야 할 때는 반드시 묻습니다.
   - 깃이 무시하던 파일(`.env`·내려받은 데이터)은 폴더와 함께 사라집니다. 남길 게 있으면
     **실행 전에** `git -C <워크트리> status --ignored` 로 보고 옮기세요(스크립트는 묻지 않습니다).
   - 🔴 `git reset --hard`·`git clean -fd`·`git stash`·force-push는 다른 세션의 일을 되돌릴 수 없게
     날립니다. **확실하지 않으면 회수하지 말고 그대로 두고 보고**합니다.
5. **정리** — 임시 파일·디버그 출력 등 이번에 만든 찌꺼기만 치웁니다.
   **내가 만들지 않은** 것은 건드리지 않습니다.
6. **커밋·푸시는 사용자가 시킬 때만.** 마감했다고 자동으로 커밋·push하지 않습니다.

## 🔴 정리 중 실패하면 — 조용히 넘어가지 않습니다 (loud-fail)

회고 기록·워크트리 회수·찌꺼기 정리 중 **하나라도 실패하면 거기서 멈춥니다.** 남은 단계를 계속
밀어붙이지 말고, **어디까지 됐고 무엇이 남았는지 + 부분 산출물의 경로**를 그대로 보고합니다.
실패를 삼키고 "마감 완료"라고 적으면, 다음 세션이 있지도 않은 상태를 믿고 시작합니다.

## 출력

마지막에 사용자에게 **딱 이 형식**으로 보고합니다:

```
✅ 한 일: …
🔍 검증: 확인함 … / 아직 안 됨 …
🌿 워크트리: 회수함 <경로> | 남겨 둠 <경로> (사유) | 해당 없음
📌 다음: … (메모: <남긴 위치>)
```

원칙: **한 것만 사실대로.** 안 한 건 안 했다고, 확인 안 된 건 확인 안 됐다고 적습니다.
