# 배송하기 (ship)

지금 폴더의 변경을 **원격 기본 브랜치까지 반영하고 뒷정리까지** 하는 한 덩어리 절차입니다.
[`worktree`](../worktree/SKILL.md)가 일을 시작하는 쪽이면, 여기는 끝내는 쪽입니다.

**본진 기본 브랜치에 직접 push 하지 않습니다. 언제나 PR 을 거칩니다.** 혼자 쓰는 레포라도
PR 이 있어야 무엇이 왜 들어갔는지 나중에 읽을 수 있고, 잘못되면 한 덩어리로 되돌립니다.

## 어디까지 갈지 먼저 정합니다

- **PR 까지** (기본) — 커밋 → push → PR 생성. 머지는 하지 않습니다.
- **머지까지** — "머지까지 해줘 / 올려서 반영해" 처럼 **머지 승인이 분명할 때만.**
  "PR 만 내줘", "머지는 하지 마" 는 당연히 PR 까지입니다. 애매하면 PR 까지만 하고 물어봅니다.

## 0. 시작 전 확인 (하나라도 걸리면 멈춤)

```bash
pwd; git branch --show-current; git status --short
```

- **본진(`~/workspace/<레포>`)에서 실행 중이면 중단합니다.** 먼저
  [`worktree`](../worktree/SKILL.md)로 폴더를 펴고 거기서 다시 시작합니다.
- 기본 브랜치 위에 서 있으면 중단합니다(그대로 push 하면 PR 없이 들어갑니다).

## 1. 커밋

- **`git add -A` 를 습관적으로 치지 않습니다.** `git status --short` 를 먼저 보고 **이번 일에
  속한 파일만** add 합니다. 관계없는 변경이 섞여 있으면 왜 있는지 확인하고 나눕니다.
- **시크릿을 눈으로 확인합니다** — `git diff --staged` 에 키·토큰·비밀번호가 보이면 중단하고
  먼저 걷어냅니다([`secret-manage`](../secret-manage/SKILL.md)). 한 번 push 하면 지워도 남습니다.
- 커밋 메시지는 그 레포의 기존 메시지 톤에 맞춥니다(`git log --oneline -5`).

## 2. push + PR

```bash
git diff origin/<기본브랜치>...HEAD --stat   # 이번 PR 에 실릴 전체 변경 확인
git push -u origin <슬러그>
gh pr create --title "..." --body "무엇을·왜"
```

- 직전 커밋만 보지 말고 **PR 전체 범위**를 봅니다. 앞 세션의 커밋이 같이 실려 있을 수 있습니다.
- 이미 PR 이 열려 있으면 새로 만들지 말고 push 만 합니다(같은 브랜치에 PR 두 개 금지).

## 3. 머지 (승인이 분명할 때만)

```bash
gh pr merge <번호> --squash
gh pr view <번호> --json state --jq .state    # MERGED 인지 눈으로 확인
```

- 🔴 **명령이 성공했다는 것과 머지됐다는 것은 다릅니다.** 위 두 번째 줄이 `MERGED` 를 찍어야
  다음 단계로 갑니다.
- 워크트리 안에서는 `--delete-branch` 를 붙이지 않습니다 — 그 브랜치를 지금 쓰고 있어서
  실패합니다. 브랜치 정리는 아래 4단계에서 합니다.
- 검사(CI)가 도는 레포면 통과를 기다립니다. 실패·충돌이면 멈추고 보고합니다. 강제 머지 금지.

## 4. 회수 (머지를 확인한 뒤에만)

```bash
cd ~/workspace/<레포>            # 지울 폴더 안에 서 있으면 지워지지 않습니다
git pull --ff-only
~/.claude/skills/session-close/scripts/retire-worktree.sh ../<슬러그>
```

- **회수 절차의 정본은 [`session-close`](../session-close/SKILL.md) 4단계**입니다 — 스크립트가 폴더·
  로컬 브랜치·**원격 브랜치**를 함께 거두고, 커밋 안 한 변경·머지 미확인이면 아무것도 지우지
  않습니다. 여기서 거두는 것은 **방금 내가 만들어 머지한 워크트리**라 승인 없이 회수합니다.
- 🔴 **머지 판정은 PR 상태(`gh`)로 합니다 — `git branch --merged` 는 squash 머지를 못 잡습니다.**
  3단계에서 `MERGED` 를 확인한 뒤에만 이 단계로 옵니다.

## 5. 보고

```
PR #<번호> <링크> — MERGED / 열림(머지 대기)
본진: pull 완료 / 미완(<사유>)
워크트리: 회수됨 / 유지(<사유>)
```

부분만 됐으면 부분만 됐다고 적습니다. 머지까지 갔다면 **회수는 여기서 끝난 것**이라
세션을 닫을 때 따로 정리할 게 없습니다.
