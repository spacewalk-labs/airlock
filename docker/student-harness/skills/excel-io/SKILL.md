# excel-io — 엑셀을 읽고 쓴다

## 0. 도구 선택 — 기본은 openpyxl 하나다

| 하려는 것 | 무엇으로 |
|---|---|
| 읽기·쓰기·수식·서식·차트·병합셀 | **openpyxl** (기본값) |
| 수만 행의 수치 집계·조인 | pandas (`uv run --with pandas` 로 부른다) |
| `.xls`(옛 포맷) | LibreOffice 로 xlsx 변환 후 처리 — 스크립트가 변환 명령을 찍어 준다 |
| `.csv` | 엑셀 도구가 필요 없다. 파일을 직접 읽는다 |

pandas 는 **서식과 수식을 전부 버린다.** 원본을 고쳐 돌려줘야 하는 일에는 쓰지 않는다.

스크립트 경로는 박스마다 다르므로 그 자리에서 푼다:

```bash
XL=$(for r in ~/.claude/skills ~/.agents/skills .claude/skills; do
       [ -f "$r/excel-io/scripts/xlsx.py" ] && echo "$r/excel-io/scripts/xlsx.py" && break
     done)
```

`uv` 가 openpyxl 을 자동으로 잡는다. 없으면 `pip install --user openpyxl` 후 `python3 "$XL" ...`.

## 1. 읽기 — probe 먼저, 그다음에만 내용

```bash
"$XL" probe 파일.xlsx                                   # ① 시트·실사용범위·헤더·타입·수식
"$XL" dump  파일.xlsx --sheet 매출 --range A3:H40        # ② 필요한 범위만 마크다운 표로
"$XL" dump  파일.xlsx --formulas --format tsv            # ②' 값 대신 수식을 보고 싶을 때
```

**시트를 통째로 읽어 컨텍스트에 붓지 않는다.** 워크북의 "사용 범위"는 서식만 남은 빈 칸 때문에
실제 데이터의 수백 배로 부풀어 있는 일이 흔하다. `probe` 가 진짜 범위와 선언된 범위를 함께 보여 주니
그걸 보고 `--range` 로 좁힌다.

`probe` 출력에서 놓치면 안 되는 세 줄:

- `header guess    row 3:` — **헤더가 1행이라고 가정하지 않는다.** 제목 배너와 빈 줄이 위에 붙어 있는
  워크북이 표준에 가깝다.
- `number-as-text` — `1,200`·`₩1,200`·`(3,400)` 처럼 기호가 붙어 문자로 저장된 숫자다.
  합계에서 조용히 빠진다 (고치는 코드는 recipes §6).
- `merged ranges` — 병합 영역은 **좌상단 칸에만 값이 있고 나머지는 None** 이다. 세로 병합된 분류
  칸을 그대로 읽으면 대부분의 행에서 분류가 사라진다.

## 2. 쓰기 — 만들고, 계산시키고, 검사한다

openpyxl 은 수식을 **글자로 적을 뿐 계산하지 않는다.** 그래서 만든 직후의 파일은 수식 칸의 값이
비어 있고, 그 파일을 `data_only=True` 로 읽는 쪽은 전부 `None` 을 본다. 세 단계를 끝까지 돈다.

```bash
# ① openpyxl 로 작성 (아래 규칙을 지키며 직접 코드를 짠다)
"$XL" recalc 산출물.xlsx              # ② 수식 계산 → 산출물.recalc.xlsx 로 나온다
"$XL" check  산출물.recalc.xlsx       # ③ 오류값 게이트. PASS 가 나올 때까지 ①로 돌아간다
```

`recalc` 는 **원본을 덮어쓰지 않고 옆에 `.recalc` 파일을 만든다.** 제자리에서 바꾸려면 `--in-place`,
다른 이름으로 내려면 `-o 경로`. 사용자에게 최종본을 건넬 때 어느 파일인지 분명히 말한다.

`check` 는 계산된 값에서 엑셀 오류코드 전부를, 수식 본문에서는 `#REF!` 만 본다 — 정상 코드인
`=IFERROR(x,"#N/A")` 를 오탐하면 게이트를 무시하게 되기 때문이다. **수식 오류가 하나도 없는 것이
납품 기준이다.** 오류가 남은 워크북은 받는 사람이 어디까지 믿어야 할지 알 수 없다.

`recalc` 에는 `libreoffice-calc` 이 필요하다.

**기존 파일을 고칠 때는 그 파일의 관례를 그대로 따른다** — 숫자 서식, 열 너비, 글꼴, 수식을 쓰는
방식, 시트 이름 규칙. 새 열 하나가 주변과 다르게 생기면 그 표는 사람이 다시 손봐야 한다.

## 3. 틀리기 쉬운 자리

**🔴 `data_only=True` 로 열어서 저장하면 수식이 값으로 영구 치환된다.** 읽으려고 연 것이 원본을
파괴하는 대표 사고다. 값이 필요하면 읽기 전용으로만 쓰고, 저장할 워크북은 `data_only=False`(기본값)로
따로 연다.

```python
wb_values = openpyxl.load_workbook(p, data_only=True)    # 읽기 전용으로만 쓴다. 저장 금지
wb_edit   = openpyxl.load_workbook(p)                     # 고치고 저장할 쪽
```

**행·열 번호는 1부터다.** `ws.cell(row=1, column=1)` 이 A1 이다. 0 부터 세면 한 칸씩 밀린다.

**`data_only=True` 인데 `None` 이 나오면 파일이 잘못된 게 아니다** — 엑셀이 그 파일을 계산해 저장한
적이 없다는 뜻이다. `recalc` 로 채운다.

**날짜는 숫자로 저장된다.** 서식이 빠진 칸은 `45000` 같은 일련번호로 읽힌다. `probe` 의 타입 요약에서
`number` 인데 날짜여야 하는 열이 보이면 서식을 확인한다.

## 4. 완료 기준

- `check` 가 PASS 다 (경고 코드 2 = 캐시 없음도 남기지 않는다 — `recalc` 를 돌린다).
- 사용자에게 보고할 때 **어느 시트·어느 범위**를 근거로 삼았는지 밝힌다.
- 숫자를 옮겨 적지 말고 `dump` 출력에서 복사한다.

서식·차트·조건부서식·시트 간 참조·병합셀 펴기·수만 행 스트리밍·pandas 왕복의 구체적인 코드는
[references/recipes.md](references/recipes.md) 에 있다 — **그런 요구가 나올 때만** 읽는다.
