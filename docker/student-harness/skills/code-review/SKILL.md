# 코드 리뷰 (code-review)

내가 방금 만든 것에는 관대해지기 쉽습니다. 변경점을 **독립적인 시선**으로 다시 보게 해 문제를 미리 잡습니다.

> ⚠️ 이 스킬 이름은 Claude Code **내장 `/code-review` 명령과 같습니다.** 이 스킬로 보게 하려면
> "**스킬로 리뷰해줘**"처럼 명시하세요 — 그냥 `/code-review` 만 치면 내장 쪽이 뜰 수 있습니다.

## 언제

- **커밋·PR·배포 전**, 큰 변경 뒤, 남에게 영향 가는 코드.

## 🔴 자기 리뷰는 리뷰가 아닙니다

**구현한 쪽이 자기 결과를 리뷰하지 않습니다.** 만들 때 놓친 것은 볼 때도 똑같이 놓칩니다
(놓친 이유가 그 사람의 가정이기 때문입니다). **독립 서브에이전트**에게 맡기세요
([`subagent`](../subagent/SKILL.md)). 내가 요약해서 넘기지 말고 **diff 를 직접 보게** 합니다 —
내 요약에는 이미 내 착각이 섞여 있습니다.

## 2축으로 — 각각 따로 돌립니다

한 에이전트에게 둘 다 시키면 섞여서 둘 다 얕아집니다. **따로** 돌리고 결과를 합칩니다.

| 축 | 이렇게 시킨다 | 무엇을 보나 |
|---|---|---|
| **일반 시선** | "이 변경이 맞는지 봐 주세요" | **정확성·엣지케이스**(빈 입력·경계값·실패 경로) · **보안/시크릿**(키·토큰이 코드나 로그에 새지 않나 — [`secret-manage`](../secret-manage/SKILL.md)) · **테스트**(바뀐 동작을 확인하는 게 있나) · **단순성** |
| **적대 시선** | "이 변경을 **깨뜨릴 방법**을 찾아 주세요" | 어떤 입력·순서·동시 실행·재시도로 무너지나. 저자가 "그럴 리 없다"고 **가정한 것**은 무엇인가 |

- **단순성** 판정 기준은 [`pikes-filter`](../pikes-filter/SKILL.md) 가 갖고 있습니다 — 그쪽으로 넘깁니다.

## 방법

1. **diff 중심**으로 본다(무엇이 바뀌었나).
2. 위 **2축을 독립 에이전트 둘**에게 각각 맡긴다.
3. 발견마다 **심각도**(높음/중간/낮음)와 **수정 제안**을 붙인다.
4. "다 됐다" 선언 직전이면 [`self-verify`](../self-verify/SKILL.md) 게이트도 통과.

## 출력

```
[일반] [심각도] 파일:줄 — 무엇이 문제 → 수정 제안
[적대] [심각도] 이렇게 하면 깨진다(시나리오) → 막는 법
…
치명적 문제: 있음/없음
```

## 주의

- 리뷰는 **고치기 전 단계**입니다 — 문제를 찾으면 고친 뒤 다시 봅니다.
- 스타일 취향보다 **정확성·안전·단순성**을 우선합니다.
