# 서브에이전트로 나눠 시키기 (subagent)

혼자 다 읽고 다 하면 **작업 책상(컨텍스트)이 금세 찹니다.** 독립적인 일은 **서브에이전트에게 나눠**
시키고 **결론만** 받으면, 내 책상은 깨끗하게 유지됩니다.

## 언제 나누나

- **넓게 찾기·조사** — 여러 파일·폴더를 훑어 **결론만** 필요할 때. 원자료를 내 맥락에 끌어오지 않습니다.
- **병렬 가능한 일** — 서로 무관한 여러 조사·구현을 **동시에**.
- **다른 시선** — 2차 구현·리뷰는 별도 에이전트, 또는 다른 모델([`codex`](../codex/SKILL.md)).
- **독립 검증** — 결과가 중요하면 [`self-verify`](../self-verify/SKILL.md)로 반박 검증.

## 어떻게 시키나 (핵심)

1. **목표 + 제약 + 반환 형식**을 명확히 줍니다. "무엇을·왜·어떤 조건으로, 결과는 이 형식으로."
2. **결론만 회수**합니다(파일 전체 X). 요약·판정·경로만.
3. 받은 결과를 그대로 믿지 말고, 중요하면 **산출물(바뀐 파일·명령 출력)로 재대조**합니다.

## 라우팅 (어디로 보내나 · 막히면 어디로)

| 상황 | 보낼 곳 | 막히면 |
|---|---|---|
| 코드베이스·문서 **넓게 찾기** | 탐색용 서브에이전트 (결론만 회수) | 범위를 좁혀 다시 시키거나 내가 직접 읽기 |
| **2차 구현·교차 리뷰** | [`codex`](../codex/SKILL.md) | 로그인 풀림·무출력이면 일반 서브에이전트로 |
| **"다 됐다" 선언 전 검증** | [`self-verify`](../self-verify/SKILL.md) | 게이트는 생략 금지 — 직접 재현으로라도 확인 |
| 웹에서 찾아 종합 | [`web-research`](../web-research/SKILL.md) | 출처를 못 대면 결론으로 쓰지 않는다 |
| 코드 품질·단순화 관점 | [`code-review`](../code-review/SKILL.md) · [`pikes-filter`](../pikes-filter/SKILL.md) | 지적에 근거(파일:줄)가 없으면 기각 |
| 무엇을 시킬지부터 안 정해졌을 때 | [`task-discussion`](../task-discussion/SKILL.md) | — |

## 주의

- 나누는 목적은 **컨텍스트 절약**입니다. 결론만 받아 책상을 지키세요.
- 🔴 **자기 리뷰 금지.** 구현한 에이전트가 자기 결과를 리뷰하지 않습니다. 리뷰·검증은 **그 일을 하지
  않은** 다른 에이전트에게 시킵니다. 자기 리뷰는 형식만 통과시킵니다.
- 🔴 **무출력·타임아웃은 통과가 아닙니다.** 답이 안 오거나 멈춘 것을 "문제 없음"으로 읽지 마세요.
  끊고 다시 시키거나, 위 표의 대체 경로로 보내거나, 내가 직접 확인합니다.
- 서브에이전트도 **틀릴 수 있습니다** — 중요한 결론은 검증 게이트를 거칩니다.
